# Troubleshooting

Repo: `/Users/agent/ai/repos/hermes-jarvis-voice`. Start with
`scripts/status.sh` (read-only) for a one-screen snapshot before anything below.

| Symptom | Check | Fix |
|---|---|---|
| jarvisd offline | `launchctl print gui/$(id -u)/local.jarvis.jarvisd \| head -20` - look for `state = running` and a `pid`. Then `curl -s 127.0.0.1:9140/health`. | If not loaded: `scripts/install.sh` (idempotent) re-bootstraps it. If loaded but crashing: `tail -50 ~/ai/state/jarvis-voice/logs/jarvisd.err.log` and `.../jarvisd.out.log` (uvicorn access/crash lines) plus `.../jarvisd.log` (app's own rotating log, all under `~/ai/state/jarvis-voice/logs/`). Manual restart: `launchctl kickstart -k gui/$(id -u)/local.jarvis.jarvisd`. |
| dashboard tab / `/jarvis` down | `curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:9120/jarvis` - expect 200. | The dashboard (`local.hermesagent.dashboard`, port 9120) is the shared main Hermes dashboard, not managed by this repo. If it's down, that affects every plugin, not just Jarvis - restart it the same way you'd restart any other Hermes dashboard issue. jarvisd itself (port 9140) can be healthy even while the dashboard tab is unreachable. |
| plugin tab missing from dashboard | `curl -s 127.0.0.1:9120/api/dashboard/plugins \| grep jarvis-voice`. If absent, check the symlink: `ls -la ~/.hermes/plugins/jarvis-voice` - must point to `<repo>/hermes-plugin`. | Re-link: `scripts/install.sh` (step 3 recreates it if stale/missing). Then reload the dashboard tab, or restart `local.hermesagent.dashboard` to force a rescan - it imports `plugin_api.py` once at startup only. |
| no speech recognized | UI shows the "Didn't catch that." hint. WS sends `{t:"state", value:"idle", detail:"no speech recognized"}` (see `docs/SPEC.md` §WebSocket). Confirm STT is actually loaded: `curl -s 127.0.0.1:9140/health \| grep -o '"stt":{[^}]*}'`. | If STT never loaded: check the Parakeet weights are cached (`mlx-community/parakeet-tdt-0.6b-v2` in the HuggingFace cache) or that faster-whisper's own weights downloaded. `component_status()` reports `"loading"` vs a real load error. If STT is healthy but a specific utterance was too short/quiet: check mic level (`micHint` in the UI, "Mic level is silent"), input device, and macOS mic permission for the browser. This is a genuine miss, not the echo guard, see the next row for that. |
| Jarvis hears itself / talks over its own reply | The `stt.ignored` event (`reason: "echo of my own speech"`) should suppress this while Jarvis is audible or within 1.5 s after, check the activity timeline for `stt.ignored` rows. If a real barge-in keeps false-triggering off Jarvis's own voice with no headphones, that's an AEC failure, not a config bug. | Confirm the browser's built-in echo cancellation is actually engaged: check `audioDiag` in the UI (System tab), it reports which output rung is active (`loopback RTCPeerConnection` is the AEC-visible path, a plain `audioCtx.destination` fallback has none). Prefer headphones or lower speaker volume, especially on a laptop mic. A missing/failed loopback rung is a per-browser AEC limitation, not fixable in `jarvisd.toml`. |
| sentences cut off mid-word (hands-free) | This was the old fixed-500ms-silence bug. It should no longer happen with Smart Turn v3.2 (`vad.engine = "smart_turn"`). Check `components.turns.detail` in `/health`, expect `"silero + smart-turn v3"`. If it says `"silero (no smart-turn model)"` or `"webrtcvad (...)"`, the endpointer degraded because a model file is missing. | Confirm `~/ai/models/silero/silero_vad.onnx` and `~/ai/models/smart-turn/smart-turn-v3.2-cpu.onnx` exist and are readable (paths from config `[vad]`). Push-to-talk is unaffected by any of this, everything between press and release is always one utterance, VAD never splits it. |
| words skipped / dropped from playback | Check the browser console/UI for player-worklet errors. This was fixed by making the player worklet's FIFO unbounded (previously a bounded queue could silently drop chunks under a burst). | If it recurs, rebuild the UI bundle (`ui/build.sh`) and confirm `hermes-plugin/dashboard/dist/player-worklet.js` is current - a stale cached worklet in the browser is the usual cause; hard-reload the tab. |
| cloud brain / cloud worker down | `curl -s 127.0.0.1:9140/health` - check `components.mediator`. `GET /brains` shows `available` per brain. The mediator auto-retries the SAME turn on the other brain if the active one fails before its first token (6 s cloud / 10 s local budget, `mediator/loop.py`). A cloud `delegate_task` also auto-retries once on the local worker backend for infrastructure failures (429/5xx/network/quota, see `docs/SPEC.md` §Worker execution). | If cloud stays down: switch manually with `POST /brains {"brain":"local"}` and/or `POST /backends {"backend":"local"}`, or just wait, the fallback is automatic per-turn/per-task, nothing is stuck. Confirm the local fallback path itself is healthy: `curl -s 127.0.0.1:8090/v1/status` (model router). If local is ALSO down, both brain and worker degrade together, fix the router first (`launchctl kickstart -k gui/$(id -u)/local.hermesagent.modelrouter`). |
| reminders not arriving | `set_reminder` replies are spoken immediately ("Okay, I'll remind you..."). The actual delivery is a jarvisd-owned timer, not a worker. Check pending rows: `curl -s '127.0.0.1:9140/tasks?status=pending'` won't show them (reminders aren't tasks), instead check `jarvis.db`'s `reminders` table, or just wait for the spoken/Matrix delivery. | If jarvisd was restarted between setting and firing: pending reminders reload on boot and fire (marked "a little late") if the due time already passed, this is by design, not a bug. If the Matrix side-channel silently fails: `~/ai/bin/notify --room jarvis-voice --plain test` should still work standalone. A missing/broken `notify` binary only drops the phone-side copy, the spoken reminder still fires. |
| mic permission blocked in browser | Browser padlock/site settings for the dashboard's origin -> Microphone. `127.0.0.1` and the tailnet https origin are both treated as secure, so `getUserMedia` should prompt; if it silently fails, check macOS System Settings -> Privacy & Security -> Microphone for the browser itself. | Grant permission, reload `/jarvis`. If still silent, check the browser console for `NotAllowedError` vs `NotFoundError` (no input device) vs a `mic-worklet.js` load failure. |
| no audio out | Confirm TTS is actually healthy: `curl -s 127.0.0.1:9140/health \| grep -o '"tts":{[^}]*}'` - expect `"ok":true,"detail":"kokoro resident"`. Test end-to-end: `curl -s -X POST 127.0.0.1:9140/say -H 'Content-Type: application/json' -d '{"text":"test","interrupt":false}'`. | If kokoro isn't resident: check `~/ai/models/kokoro/kokoro-v1.0.onnx` and `voices-v1.0.bin` exist and are readable. If kokoro fails to load, jarvisd falls back to macOS `/usr/bin/say` - confirm `say` still works standalone. In-browser: check `player-worklet.js` loaded (Network tab) and the tab isn't muted/backgrounded (Safari suspends audio contexts in background tabs). |
| worker tasks failing / stuck | `curl -s 127.0.0.1:9140/tasks/<id>` for its status/summary. Smoke-test the backend directly. Cloud: `hermes -p default -z "Reply with exactly: JARVIS-OK" --yolo --ignore-rules`. Local: `HERMES_HOME=~/ai/state/jarvis-voice/hermes-home hermes -z "Reply with exactly: JARVIS-OK" --yolo`. Verify the local model is up: `curl -s 127.0.0.1:8090/v1/status`. | If the cloud smoke test fails: that's an OpenCode Go / jev-router problem, outside this repo, check the `default` Hermes profile directly. If local fails: cold router load adds ~8 s, and a long-context task can legitimately take minutes. A task stuck past `worker.timeout_s` (900 s default) gets killed and marked `failed` automatically, it should never hang forever. |
| memory search empty | `curl -s '127.0.0.1:9140/memory/search?q=test&k=3'`. Check `components` under `/health` for the embeddings/memory row. | Reindex is incremental and in-process on jarvisd's own 10-minute schedule. A full restart also triggers a fresh incremental pass: `launchctl kickstart -k gui/$(id -u)/local.jarvis.jarvisd`. Confirm Ollama has `nomic-embed-text` pulled (`ollama list`) and reachable, embeddings silently skip (not error) if Ollama is down. |
| high RAM usage | `curl -s 127.0.0.1:8090/v1/status`, `memory_pressure -Q` (trustworthy). Do NOT read `vm_stat`'s "Pages free" as headroom - file-backed pages are reclaimable and it reads alarmingly low when nothing is wrong. | The router idle-unloads gpt-oss-20b after 900 s on its own. If memory is genuinely tight, that's a model-router concern, not a jarvisd one - jarvisd's own footprint (STT + TTS + service) is well under 1 GB. |
| where are the logs | `~/ai/state/jarvis-voice/logs/`: `jarvisd.log` (app's own rotating log), `jarvisd.out.log`/`jarvisd.err.log` (LaunchAgent-captured stdout/stderr - uvicorn access lines and anything printed/crashed outside the app's logger). No separate dashboard logs here - those belong to `local.hermesagent.dashboard`. | See `docs/MAINTENANCE.md` §Log rotation for rotation/retention details. |
| false `Unauthorized` on `/api/plugins/...` or `/api/dashboard/plugins/rescan` | A bare `curl` against these dashboard routes returns `{"detail":"Unauthorized"}` - this is correct behavior, not a bug. The dashboard gates its API behind a per-session token (`window.__HERMES_SESSION_TOKEN__`, header `X-Hermes-Session-Token`). | From a browser (already authenticated) it works. From the CLI, either copy the token out of the browser's Network tab, or hit jarvisd directly on `127.0.0.1:9140` (no auth, loopback-only) instead of going through the dashboard proxy on 9120. |

## Phone (iPhone Safari / PWA)
| Symptom | Cause / fix |
|---|---|
| No sound from Jarvis | Tap anywhere once after opening (audio unlocks on a gesture). If it still fails, force-close the home-screen app so it loads the current bundle. System tab shows the output path (iOS: `direct`). |
| Tapping Tasks/Memory/Activity only darkens the screen, or nothing is clickable | Old hermes-ui (< 1.5.5) overlay bug in WebKit. Check `hermes-plugin/dashboard/dist/hui/VERSION`, run `~/ai/repos/hermes-ui/bin/hui-sync --all`. |
| Live caption loses the start of the sentence | Fixed 2026-09-28: the mic-left-on turn now ends after 2.5 s of silence (`vad.ptt_silence_ms`). |
| Page zooms when typing | Inputs must be 16px on touch (hermes-ui 1.5.5). |
