## Design (implemented in service/memory/)
- SQLite (jarvis.db) tables: notes(path, mtime, title, folder, frontmatter json, content_hash),
  chunks(note_id, ord, text), chunks_fts (FTS5), embeddings(chunk_id, vec BLOB 768 float32),
  aliases(entity, chunk/note ref). Incremental by mtime+hash; full reindex < 10 s for 384 KB.
- Query: exact alias/entity → FTS5 BM25 → cosine on nomic embeds (Ollama /api/embed) →
  weighted merge with folder priors (30/40/20/10 boost, 80/90 penalty), recency decay on
  `updated`, confidence field if present. Return: source path, snippet, score, confidence,
  updated. Context card ≤ configurable token budget (default ~600 tok), dedup by note.
- Contradiction flag: same entity, conflicting values across notes → both returned + `conflict: true`.
- Writes: ONLY new notes to 00-inbox via memory-capture.sh conventions (redaction), frontmatter
  `source: jarvis`, `status: triage` — reviewable, never edits existing notes.
